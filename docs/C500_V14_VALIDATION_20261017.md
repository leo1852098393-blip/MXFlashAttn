# MXFlashAttn v1.4.0 C500 验证摘要

**日期**: 2026-10-17  
**代码线**: `dev/v1.4.0`  
**本地源提交**: `92e9ee8`  
**远程部署提交**: `044d46c1a15a2fa9b70bfa3e552feecdec1b4c9f`

## 环境

- MetaX C500 64GB，单卡
- MACA `3.5.3.20`
- 驱动 `3.8.30`
- MetaX PyTorch `2.8.0+metax3.5.3.9`
- `flash-attn 2.6.3+metax3.5.3.9torch2.8`
- `vllm 0.17.0`
- 模型来自 `/mnt/moark-models` 只读共享模型盘

## 通过项目

- C500 环境探针通过，Python 能识别 MetaX C500。
- ATen correctness 扩展、v7 对照扩展和 M1 Split-KV 扩展编译成功。
- 项目测试：`78 passed`。
- 发布审计通过，无敏感信息发现。
- Qwen3-0.6B vLLM baseline/candidate 真实生成通过，candidate 记录到 6944 次 `vendor_direct` decode 事件。
- Qwen3-4B batch=32、1024 token 真实 E2E：
  - v7：`357.98 tok/s`
  - M1-UM：`1312.86 tok/s`
  - M1-UM2：`1306.66 tok/s`
  - M1 dispatch：`36864`
  - 相对 v7：约 `3.67x`
- Qwen3-8B batch=16、256 token 真实 E2E：
  - v7：`509.65 tok/s`
  - M1-UM：`684.60 tok/s`
  - M1-UM2：`689.04 tok/s`
  - M1 dispatch：`9216`
  - 相对 v7：约 `1.35x`
- M1 算子级矩阵的已执行支持配置 correctness 通过，覆盖 FP16、BF16、GQ=2/4/8、head_dim=64/128、溢出边界和 8192 上下文。

## 限制和未完成项

- M1 在低并发/短序列不保证加速。Qwen3-4B batch=16、64 token 场景中，M1 低于 v7。
- Qwen3-4B 和 Qwen3-8B 的小样本文本匹配不是 4/4，不能写成严格的逐 token 一致性证明。
- Qwen3.5-9B head_dim=256 没有进入 `m1_split_decode`，而是走 `native_decode` 回退，guard 生效；该场景文本匹配为 `0/4`，不作为 M1 正确性通过证据。
- 完整 M1 稳健性脚本在预期不支持的 GQ=3 case 处停止，这是脚本没有隔离 guard case，不代表支持配置失败。
- 本轮仍未完成统一 TTFT/P95 测量；vLLM 0.17.0 离线接口未提供完整的首 token 时间戳。
- 日志中的 `libcudart.so.12` FA2 探测告警来自 MetaX/vLLM 通用探测，不影响本轮实际 MACA provider、M1 内核和 vLLM 生成结果。

## 结论

v1.4.0 开发线已经在新 C500 实例上完成部署、编译、算子验证和真实 vLLM 生成。核心 M1 Split-KV decode 在 Qwen3-4B 长 decode 场景复现约 3.67x 相对 v7 的吞吐提升，并在 Qwen3-8B 上复现约 1.35x。

当前不应把 v1.4.0 标记为最终发布版本：Prefill 的真实性能、TTFT/P95、严格 token-level 长尾一致性和 guard 自动化隔离仍需后续处理。PyPI 发布继续延期到这些工作完成之后。
